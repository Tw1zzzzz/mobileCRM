# Pulse для Android — план и статус

Ветка: `android`. iOS-проект остаётся на своих местах (`Pulse/`, `PulseWidgets/`, `Shared/`), чтобы изменения
из `main` вливались без конфликтов. Рядом появляются:

```
core/         Kotlin Multiplatform: модели, расчёты, хранилище, API — общее для Android (и позже iOS)
androidApp/   Android-приложение на Jetpack Compose
```

Стек: Kotlin, Kotlin Multiplatform, Jetpack Compose, kotlinx.serialization, kotlinx.datetime, Ktor,
Health Connect, WorkManager, Glance. Минимальная версия — Android 9 (API 28).
Модуль ядра называется `core`, а не `shared`: на macOS имена папок без учёта регистра, и `shared` совпал бы
с iOS-папкой `Shared/`.

ID приложения пока `com.pulsecrm.mvp` (как на iOS) — меняется до первой загрузки в Google Play.

Формат данных совпадает с iOS: JSON, даты ISO 8601, те же поля — данные и будущий сервер общие.

## Сборка

```bash
./gradlew :core:allTests                 # тесты ядра
./gradlew :androidApp:testDebugUnitTest  # тесты Android-части, включая UI-тесты Compose (Robolectric)
./gradlew :androidApp:lintDebug          # lint: 0 ошибок и 0 предупреждений, исключения — в androidApp/lint.xml
./gradlew :androidApp:assembleDebug
./gradlew :androidApp:assembleRelease --no-configuration-cache   # release с R8
```

UI-тесты Compose идут на JVM в Robolectric с песочницей Android 14 (SDK 34): для более новых песочниц нужна Java 21,
а проект собирается на 17. Первый запуск скачивает песочницу (~10 минут).

Release собирается только без configuration cache: задача Compose-компилятора `produceReleaseComposeMapping`
не умеет кэшироваться. Для отладочных сборок кэш остаётся включённым.

## Синхронизация данных

Контракт сервера — в [API.md](API.md). После входа в настоящий аккаунт приложение один раз загружает данные с сервера за экраном «Загружаем ваши данные…». Дальше синхронизация идёт в фоне через WorkManager: через 10 секунд после изменения, когда приложение уходит в фон, и при каждом запуске приложения; нужна сеть, при ошибке раунд повторяется с экспоненциальной задержкой (от 30 секунд). Записи двух телефонов сливаются по одной (удалённые записи не возвращаются). Демо-аккаунты и локальная сборка без сервера не синхронизируются никогда. При выходе приложение до 5 секунд пытается отправить неотправленные изменения, после чего выходит в любом случае; данные остаются на телефоне. Чтобы сбросить синхронизацию на тестовом устройстве, очистите данные приложения: `adb shell pm clear com.pulsecrm.mvp` — после следующего входа данные снова загрузятся с сервера.

## Стафф и команда (сборка с сервером)

- Регистрация, роль «Стафф»: сегмент «Создать команду» / «Вступить по коду стаффа». В первом случае вводится «Название команды», во втором — поле «Код стаффа» (код даёт стафф команды; в API это `staff_code`, см. [API.md](API.md)). Сегмента нет в локальной сборке без сервера: там вступать некуда.
- Профиль стаффа, карточка статуса: строки «Код для игроков» (`invite_code`) и «Код для стаффа» (`staff_code`). Сервер отдаёт коды только стаффу команды, у остальных строк нет.
- Кабинет стаффа в браузере (`/staff`) — отдельный сайт на том же сервере: [STAFF_PANEL.md](STAFF_PANEL.md).

## Проверка на эмуляторе

```bash
# эмулятор с окном (AVD PulsePixel, Android 16)
$ANDROID_HOME/emulator/emulator -avd PulsePixel
# или без окна
$ANDROID_HOME/emulator/emulator -avd PulsePixel -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect
# тестовые данные в Health Connect (только debug-сборка; сначала выдать WRITE_* из src/debug/AndroidManifest.xml через `adb shell pm grant`)
adb shell am broadcast -n com.pulsecrm.mvp/com.pulse.android.debug.SeedHealthReceiver
# открыть экран сразу: --es demo player|solo|staff --es route sleep|fitness|screen|calendar|…
adb shell am start -n com.pulsecrm.mvp/com.pulse.android.MainActivity --es demo player --es route sleep
```
